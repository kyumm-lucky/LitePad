# LitePad

macOS 原生轻量文本编辑器骨架：Swift + SwiftUI 外壳 + AppKit `NSTextView` 编辑核心，定位类似 Notepad++ 的 macOS 平替，安装包量级为原生体积（远小于 Electron 方案）。

## 功能现状

- **页内多标签**（Notepad++ 式）：点击切换、单个关闭、"+" 新建；`Cmd+N` 新建、`Cmd+O` 打开、`Cmd+S` 保存、`Cmd+W` 关闭当前标签
- **标签右键菜单**：六项固定顺序——关闭当前文件 / 关闭非当前文件 / 关闭左边所有 / 关闭右边所有 / 关闭所有 + 打开文件所在位置（在 Finder 中打开所在文件夹并选中该文件；未标题标签置灰）。作用对象是右键点中的那张标签，弹出菜单本身不改变活动标签；作用集合为空的项（最左标签上的「关闭左边所有」、只剩一张标签时的「关闭非当前文件」等）置灰；关闭族与文件菜单的「关闭全部」共用同一条两阶段收尾路径：先逐个确认有改动的标签、任一取消即中止，全部通过后才统一关闭
- **批量与收尾**：文件菜单里的「保存全部」一次写盘所有有改动且已绑定文件的标签（未标题的脏标签跳过并汇总提示一次）、「关闭全部」收尾后只剩一个空标签（窗口保留）、「打开最近」里有「清空最近」
- **未标题标签命名**：标题按「新文件1」「新文件2」……依次编号，序号取当前已打开标签中出现过的最大序号 + 1，标签存活期间不变；另存为面板的默认文件名取该标题
- **未标题文稿的异常恢复**：未标题标签的正文会去抖写入独立的恢复区（`~/Library/Application Support/LitePad/Recovery/entries.json`，单条上限 1 MiB、最多 16 条），崩溃或强制退出后重启会提示恢复并列出条目数与标题；「恢复」把它们建回标签页（内容不带保存基准，因此仍是未保存状态），「放弃并删除」是不可逆的批量删除。四个出口——正文被清空、关闭标签、正常退出时确认通过、另存为并绑定文件——都会把条目移出，用户明确丢弃过的内容不会复活；恢复区写不进去或超限时会显著提示，不会让用户以为内容受保护。读侧把「文件不存在」「读不出来」「内容损坏」分开：读失败时本次运行不改写恢复区文件，以免覆盖盘上仍在的草稿
- **拖拽文件入窗**：把文件拖到窗口任意位置（编辑区、标签栏、状态栏）即打开为标签页，拖入过程中整片可投放区亮起接收提示，同一文件已打开则切回原标签；目录与图片 / 影音 / 压缩包这类非文本被过滤并汇总提示一次。编辑区由编辑视图在 AppKit 层接管投放（可编辑的文本视图会先消费落在文字区的投放，其后的 SwiftUI 投放目标收不到事件），标签栏与状态栏由主栏外层接住
- **编辑核心**：`NSTextView`，等宽字体、软换行、系统级撤销/重做、关闭自动引号/破折号替换
- **编辑手感**：回车继承当前行的行首空白，在可见的块开头（`{`、`(`、`[`、`:` 一类，按语言定义里的块起始字符）之后再加一级缩进，纯文本与未知扩展名只继承不加级；`Tab` 按设置插入空格或制表符；缩进宽度（1–16）是单一来源，同时驱动插入的缩进、制表位换算与缩进指示线的绘制。选中文字后状态栏显示选区的字符数与词数，编辑区高亮该词在全文中的所有出现（字面匹配，命中超过一千不启用）
- **行操作**（菜单栏「编辑 → 行操作」，同时是工具抽屉里的第七个工具，两处共用同一份纯逻辑）：升序 / 降序排序、去重、删除行尾空白、合并行、转为大写 / 小写、添加 / 取消行注释；作用于选区覆盖到的整行（无选区时是全文），按各行的原有行尾拆行并保留、不统一行尾，一次 `Cmd+Z` 回退整次操作；没有行注释符号的语言其注释两项置灰。「删除行尾空白」只去掉空格与制表符（不换行空格、全角空格等不动），与保存时清理同一口径
- **语法高亮**（正则版，按扩展名自动识别）：HTML / XML / SQL / Java / Python / JavaScript / JSON，其余按纯文本处理
- **语法配色主题**（设置页「外观」）：内置跟随系统 / 经典 / 高对比三套，各自区分浅色与深色取值并随系统深浅切换；六个语义角色（基色、注释、字符串、数字、关键词、标签）与装饰层、行号栏的用色都来自主题。只做内置固定几套，不做主题编辑器与外部主题文件
- **行号栏**：随滚动与编辑刷新
- **显示菜单**：在框架自带的「显示」菜单里补上「增大字号 / 减小字号 / 复位字号」（`Cmd+=` / `Cmd+-` / `Cmd+0`，字号范围 6–96，复位回设置项的默认值 13）与五项带勾选的显示开关（软换行、行号、不可见元素、缩进指示、当前行高亮），勾选状态与设置页双向一致；「不可见元素」这一项只切总开关，五个子项仍由设置页控制
- **窗口尺寸**：历史窗口位置与尺寸优先，设置页里的固定尺寸只在没有历史记录时作为初始值（改由场景的默认尺寸修饰符承载）
- **打印**（文件菜单 `Cmd+P`）：把当前文稿交给系统打印面板，面板以窗口内的表单呈现；打印用一份专供打印的视图——按可打印宽度排版、正文强制深色、不带高亮与装饰层，不印行号与页眉页脚
- **查找 / 替换**（`Cmd+F` 开合面板，编辑区右上悬浮）：上一个 / 下一个（回车同「下一个」）、替换当前、全部替换，可选正则 / 大小写 / 全词，实时显示「第几个 / 共几个」，正则非法时直接标红。两个输入框都支持转义表达换行等：`\n` 换行、`\r` 回车、`\t` 制表符、`\\` 反斜杠，未识别的 `\x` 原样保留（`C:\Users` 这类路径不受影响）；`\n` 与 `\r\n` 都按「换行」处理，LF / CRLF / 经典 Mac CR 以及混合行尾的文档都能命中，替换时插入的是文档自身的换行符；粘贴多行文本进单行输入框会自动转成 `\n` 转义
- **未保存保护**：关闭有更改的标签、退出应用（`Cmd+Q` / 菜单退出 / Dock 退出 / 注销）时逐个弹窗（保存 / 不保存 / 取消）；取消或保存失败则中止退出；标签页与状态栏显示未保存状态
- **转码失败不落盘**：所选编码无法表示正文时保存报错、不写盘、标签保持未保存状态（不再兜底写出 0 字节文件）；自动保存连续失败只显著提示一次，避免与「尚未保存」混同。只读文件不构成保护——原子写会绕过文件自身的写权限，这类失败请用只读目录验
- **保存时清理**（设置页「通用」，默认关）：「保存时删除行尾空白」「保存时补齐末尾换行」两项只在显式保存（含关闭标签与退出时的确认保存）前执行，自动保存不改动正文；清理在编辑视图内经撤销协议执行，按一次 `Cmd+Z` 可整体回退到清理前。「删除行尾空白」只去掉空格与制表符，与编辑菜单里的同名行操作同一口径；两项都不是保义操作（Markdown 的行尾双空格是硬换行、补丁文件的空行有意义），设置项里可按内置语法排除
- **按编码重读磁盘**：状态栏编码下拉里的选项只改保存编码，下面的「按此编码重新载入」才按它重读正文——重读走严格解码 + 字节往返校验，读不通就报错并保持原内容 / 原编码 / 未保存状态，不会把读错的正文立成新基准；标签有未保存改动时先走三键确认，输入法组字期间拒绝
- **窗口重开**：红色按钮关掉窗口后（应用仍在运行）再点 Dock 图标 / Dock 的「重新打开」会把窗口建回来，标签与未保存内容随会话保留；`Cmd+H` 隐藏与最小化由系统直接恢复
- **从系统打开文本文件**：`Info.plist` 用父类型 `public.text` 一条主声明（`LSHandlerRank=Alternate`，不抢系统默认编辑器）覆盖 `.json`、`.xml`、`.html`、`.css`、`.yaml` 这类不 conform 到 `public.plain-text` 的文本类型，另加一条 `com.apple.property-list` 覆盖 `.plist`；`.ts` 故意不声明（系统把它归为传输流视频类型）。双击、右键「打开方式」、拖到 Dock 图标都会开进当前窗口的标签页，同一文件已打开则切回原标签。主窗口用单窗口场景（`Window`），`WindowGroup` 会为每个「打开文稿」事件自建窗口、导致同一文件既有新标签又多一个窗口；冷启动时先缓冲文件等会话就绪，窗口全关时自动重建窗口
- **工具**（标签栏右侧扳手按钮下拉，样式与状态栏下拉一致；菜单栏「工具」同入口）：窗口右缘滑出的通栏抽屉（高度与窗口一致，弹簧曲线滑入滑出并带左侧投影），左缘可拖拽调宽（悬停时亮起提示条），各工具分别记住自己的宽度，输入默认取编辑器选区（无选区取全文），结果可复制或写回编辑器（`Cmd+Z` 可回滚）
  - **Unicode 转义**：`\uXXXX`（非 BMP 用代理对）编解码，解码兼容 `\u{XXXXX}`、`\xXX`、`\UXXXXXXXX`、`U+XXXX`
  - **ASCII 码**：字符 ⇄ 码值数字串（十进制 / 十六进制，含中文等非 ASCII 字符），解码兼容 `0x` 前缀与逗号 / 分号 / 换行分隔
  - **URL 编码**：UTF-8 百分号编解码，可选空格编码为 `+`
  - **Base64**：编解码，支持 URL 安全变体（`-` `_`、省略 `=`）；解码忽略空白换行，非 UTF-8 结果给出提示
  - **JSON 格式化**：格式化（2 / 4 空格缩进）与压缩；只重排结构之间的空白，键顺序、数字写法（`1.0`、`1e5`、大整数）与转义原文都原样保留，空对象 / 空数组仍写作 `{}` / `[]`；语法错误按「第 N 行第 M 列」给出中文原因（注释、尾随逗号、单引号字符串等常见写法单独指明）
  - **字符串对比**：A / B 两栏（A 可取编辑器选区、B 可取其他标签页）逐行对比，差异行红绿标记 + 行内字符级高亮，可选忽略大小写与行首尾空白，差异可导出为 `+` / `-` 文本
  - **哈希计算**：MD5 / SHA-1 / SHA-256 / SHA-512（默认 SHA-256）十六进制摘要，可选大写；结果与系统命令行工具（`md5` / `shasum`）逐字节一致
  - **UUID 生成**：凭空生成一个 UUID（打开工具或点「重新生成」换一个），可选大写；不需要输入，输入为空时复制与写回一样可用
  - **时间戳互转**：Unix 秒 / 毫秒与本地时间字符串双向转换（识别本地 `yyyy-MM-dd HH:mm:ss[.SSS]`、`yyyy/MM/dd …`、不带时区的 ISO 8601 与带 `Z` / `±HH:MM` 的写法），「现在」按钮填入当前时间；整串必须完整识别，认不出的按失败给出中文原因
  - **HTML 实体**：编解码，编码覆盖 `&` `<` `>` `"` `'` 与不换行空格（可选连非 ASCII 一起转义），解码支持命名实体（符号、排版标点、箭头、数学、希腊字母、常见重音拉丁字母）与十 / 十六进制数字实体，未收录的名字原样保留
  - **动效**：切换分段控件时选中胶囊像一滴水先横向拉长再回弹收回（`Views/LiquidSegmented.swift`，自绘并带无障碍语义）；切换工具时面板内容按工具在列表中的前后关系定向推入推出；标签栏扳手在工具打开时拧转并染强调色。所有曲线集中在 `Views/Motion.swift`，并遵循系统「减弱动态效果」设置
- **打包**：`make app` 一键产出 `.app`（ad-hoc 签名，并在签名之后刷新系统的文档类型登记），`make dmg` 产出带拖拽安装链接的 DMG；图标为矢量脚本绘制（黑底 + 白纸 + 文字行与光标，`make icon` 可重新生成 `.icns`）

## 环境要求

- macOS 13+
- Swift 5.9+（Xcode 或 Command Line Tools 均可，本机仅需 `swift build`）

## 快速开始

```bash
make run    # 开发调试（裸进程运行，菜单栏可能不完整，正式体验建议用 .app）
make app    # 构建 build/LitePad.app
open build/LitePad.app
make icon   # 重新生成 Resources/AppIcon.icns（预览 build/AppIcon-1024.png）
make dmg    # 构建 build/LitePad-0.1.0.dmg
make clean
```

## 设计说明

- **为什么编辑器核心不用 SwiftUI `TextEditor`**：macOS 上它在行号、高亮定制、大文件表现上都不够用；`NSTextView` 免费提供撤销/重做、输入法与文本存储管理，通过 `NSViewRepresentable` 桥接进 SwiftUI。
- **高亮实现**：v1 为"全文重刷 + 规则优先级跳过"的正则方案（注释 > 字符串 > 数字 > 关键词 > 标签），逻辑简单可靠；代价是大文件逐键性能一般。
- **标签切换**：以 `tab.id` 重建编辑视图，避免多标签间的文本与选区串扰。
- **JSON 工具为什么不走 `JSONSerialization`**：解析成对象再序列化会丢掉键顺序，并把 `1.0`、`1e5`、超出双精度的大整数改成别的写法，写回编辑器等于改了原文；改为按记号重排原文后，格式化 / 压缩只动结构之间的空白，键顺序、数字写法与转义原文都原样保留，报错也能精确到行列（`Tools/JSONFormatter.swift`）。
- **查找 / 替换为什么用转义表达换行**：面板是单行输入框，输不进真实换行，`\n` 因此成了唯一表达方式——查找侧展开为 `(?:\r\n|\r|\n)`，一条 `\n` 在 LF / CRLF / 混合行尾的文档里都能命中；替换侧插入标签页当前的行尾（状态栏显示的那个，保存写盘也按它统一），不制造混合行尾。正则模式下 ICU 的原生 `\n` 只认 LF，同样改写成「任意换行」，而字符类内的 `\n` 与 `\\n` 保持原样；ICU 替换模板不认 `\n`（会退化成字母 n），所以模板里的换行 / 制表符也在这里先展开（`Model/FindSyntax.swift`）。
- **`Cmd+W`**：自定义的"关闭标签页"与系统"关闭窗口"共存在 File 菜单中，如发现快捷键被系统项抢占，可在菜单栏手动确认优先级。
- **为什么保存链路要求「可失败」**：编码转换原本在失败时兜底成空数据，一旦正文里有该编码表示不了的字符，保存会写出 0 字节文件并把它当成「已保存」；同一个坑还有三条：宽容解码把错误编码当成合法正文、据此建立干净基准后下一次写盘覆盖原文、经符号链接写盘会把链接本身替换成普通文件。现在的口径是「任何建立保存基准的转换都必须可失败」——读侧（按编码重读、外部改动重载）也做**字节往返校验**（读出的正文按同一编码再编码必须与磁盘字节一致），失败即保持原内容、原编码与未保存状态（`Model/FileFormat.swift`、`Model/EditorSession.swift`）。
- **为什么整串替换要先清空撤销栈**：整串赋值或替换不会清掉已经登记到撤销管理器的动作，它们记的是旧文本上的区间，之后按 `Cmd+Z` 会在失效区间上抛未捕获异常并**终止进程**（崩溃还是延迟的，未保存内容一并丢）。因此任何「把整串文本交给编辑视图」的同步都先 `removeAllActions()`，重读与外部改动重载这类整串改动一律走撤销协议而不是赋值；模型侧整串替换（无视图的标签）之后必须重算查找匹配区间，否则后续替换会在新文本之外拼接区间（`Editor/CodeTextView.swift`、`Model/EditorSession.swift`）。
- **一个已解析路径只对应一个标签**：打开、拖入、另存为都经同一份判定（规范化 + 解析符号链接）；打开时就把链接解析掉并把解析后的地址绑给标签，避免同一文件被两张标签持有、其中一个被外部改动检测静默重载，也避免经链接写盘把链接换掉。
- **恢复区为什么独立于会话恢复**：会话恢复（`lastSession.urls`）只记文件路径，承载不了未标题正文，也分不出「崩溃」与「正常退出」。恢复区因此是并列的另一条持久化通道，条目按**稳定标题**为键（标签的运行时标识每次启动都是新值，按它做键会让恢复出来的条目永远删不掉），删除写成墓碑并在四个出口收尾，且写入失败必须能上报——用无法报错的持久化形态会把「内容不丢」悄悄降级成无保护。读侧把「文件不存在」「读不出来」「内容损坏」分开：读失败禁止整区重写，以免覆盖盘上仍在的草稿（`Model/RecoveryStore.swift`）。
- **窗口尺寸的优先级**：历史 frame > 设置页里的固定尺寸。设置里的固定值改由场景的默认尺寸修饰符承载，其语义正是「没有历史记录时才使用」；原先在 `onAppear` 里施加尺寸的做法每次启动都会盖掉系统已恢复的 frame。也不要自行设置窗口的 frame 自动保存名——系统已按场景占用它（`NSWindow Frame main`），重设会分叉出第二个键。
- **语法主题为什么显式重跑高亮**：高亮颜色是写进文本存储的属性、装饰层与行号栏按外观解析取色，都不会自己跟着外观变；换主题或系统深浅切换时必须重刷。另：高亮的优先级守卫（「已着色则跳过」）原先拿硬编码的基色比对，主题化后必须换成同一份主题基色，否则守卫失效、块注释与字符串的着色边界会错（`Editor/SyntaxHighlighter.swift`）。
- **缩进宽度是单一来源**：插入的缩进、制表位换算与缩进指示线的一级宽度共用同一口径，否则会出现「缩进两格但指示线每四格一条」的矛盾；制表位自段落原点（含行内边距）起算，指示线的 x 也要加上这段边距才对得齐（`Editor/EditorDecorations.swift`）。
- **标签右键菜单与「关闭全部」共用一条收尾路径**：先按索引快照作用集合、逐个确认期间不动任何标签也不删恢复区条目、全部通过后统一关闭，任一取消即中止；置灰判定与作用集合取自同一份计算，避免「亮着却无事可做」（`Views/TabBarView.swift`、`Model/EditorSession.swift`）。
- **图标**：不用位图素材，`scripts/make-icon.swift` 按 macOS 图标网格（1024 画布内 824 见方、圆角 186）用 Core Graphics 画黑底圆角方块 + 白纸 + 六行文字条与蓝色光标，经 `iconutil` 转成 `.icns`；改配色或形状只需改脚本顶部的常量再 `make icon`，小尺寸由 1024 母版高质量缩放得到。
